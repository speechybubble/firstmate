# Task context and learning

Use task pickup when relevant prior context can change the next decision, and learning disposition when a candidate lesson has evidence.
A fresh routine task with no relevant history needs neither a recall exercise nor a context form.
Use existing briefs, progress notes, task records and reports rather than creating a memory store or context sidecar.
The current role and write boundaries remain authoritative: workers use only sources granted by their brief and route supervisor-memory candidates to firstmate in their permitted report or status channel.
This skill does not expand source access or authorize unrestricted transcript mining, another home's endpoint inspection, delegation, deployment or previously cancelled work.

## Task pickup

1. Read the current request or brief, latest applicable steering and linked evidence.
   Stop retrieval when the supplied context suffices for the next decision.
   If something material is missing, name the question before choosing another source.
2. Bound recall to that topic, workspace and authorized sources.
   Prefer linked reports and relevant current artifacts or code history; follow a cited older rejection when it resolves the question rather than imposing an arbitrary time window.
   Copied-file modification times and identifier order do not establish event chronology.
   An unavailable source remains an explicit evidence gap; report a material gap through the existing task channel without expanding access or inventing its contents.
3. Preserve provenance when compressing context.
   Distinguish user words and requests by reference from source requirements, optional advice, current artifact facts and agent inference.
   Carry material order, conditions, negation and exceptions, including the latest correction and the scope it supersedes.
   Advice does not become user authority, and an inferred habit does not become a stated preference.
4. Check volatile facts against their actual owner only when the next action depends on them.
   A reported shipment is not proof of current deployment; a reverted approach remains rejected unless later evidence changes that conclusion.
   Firstmate's current-state and intent owners remain authoritative; this historical summary replaces neither.
5. Put only decision-changing context in the existing `## Firstmate spec` or permitted progress note/report.
   Include the observable outcome, applicable correction, relevant artifact or revision, rejected approach and reason, scoped preference or domain exception with its source, remaining gap and next action only where each matters.
   Keep original user intent under its existing heading, following [`bin/fm-dod-lib.sh`](../../../bin/fm-dod-lib.sh) rather than putting derived recommendations there.
   Use source pointers the receiving owner can still access.
6. Include a discriminating caller example when it resolves ambiguity: action, visible result and relevant exception or recovery.
   For example, a requirement to read a foundation guide before advanced work *for new users* preserves both that order and condition; optional advice stays optional and returning users are not given a new prerequisite.
   One sentence can suffice; richer product/tutorial methods belong to their existing owner.
7. At pickup, use the saved fact to select the next action and check that the latest correction still changes acceptance.
   Preserve cancelled work as cancelled and retain contrary evidence and valid neighboring behavior.
   Record the changed decision and its result in the existing task artifact, not merely that memory was loaded.

## Learning disposition

1. Admit a candidate only from an explicit preference or correction, a verified mistake, or an evidenced reusable success.
   Read the existing owning instruction or record before choosing a change.
   A transient tool failure or lucky success is insufficient evidence for a standing lesson.
2. For a correction, verified mistake or evidenced reusable success, classify the supported source or cause before choosing disposition: instruction body, activation trigger, execution, structural behavior, or unknown.
   Use the supplied evidence and existing owner; stop when they suffice, and retain unknown rather than requiring a new investigation when attribution is unsupported.
   For failures, distinguish missing or wrong guidance, missed discovery, noncompliance with adequate guidance and structural defects; correct execution without duplicating adequate rules, fix discovery at its owner, or route structural defects to the existing repair owner.
   For successes, distinguish useful guidance, successful discovery, compliant execution and structural support; retain an existing adequate rule rather than duplicating it, and qualify any unsupported attribution.
   When actual causal investigation is needed, use [`diagnostic-reasoning`](../diagnostic-reasoning/SKILL.md) within the assigned scope.
3. For a preference, preserve the user's words, scope and source.
   One explicit correction needs no repetition threshold; a temporary request stays task-local and inferred habits remain qualified.
   A newer explicit instruction supersedes only its affected scope, preserving unrelated preferences.
   Repetition inside one conversation is not evidence from independent sessions.
4. Choose a new, duplicate, superseding, obsolete or insufficient-evidence disposition and route it through [`AGENTS.md` section 6](../../../AGENTS.md#6-project-and-knowledge-management).
   Workers report private/shared preference candidates to firstmate instead of editing its memory files.
   Follow [`stow`](../stow/SKILL.md) for curation and retention at its existing entry point, preserving its write authority, clocks and open-work persistence.
   Reusable product-control knowledge belongs with the project's existing verification or feature-map owner rather than a competing recipe.
5. Make only an authorized change at the narrowest existing owner, preserving prior instruction bytes in version control or a dated backup and preserving unrelated content.
   Prefer a rewrite or pointer over a duplicate rule; do not turn every lesson into a skill.
   If a worker can only propose the change, report that disposition honestly rather than claiming it was installed.
6. Name the future decision the retained fact changes and the evidence supporting it.
   On the next related task, retrieve it through task pickup, check it against the relevant current artifact, and record the actual changed choice and outcome.
   This reuse is conditional on related work, not a new scheduled sweep or background process.
